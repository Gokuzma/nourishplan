what should improve. Four parallel fronts: test suite, TypeScript health, UX/philosophy
coherence, live deploy/data integrity. Companion structural map: `.planning/codebase/`.

## Recommendations (prioritized)

### P0 — security / correctness

1. **Rotate the service-role key.** `.recipe-import/backfill-meal-types.py` (untracked) hardcodes it; `.recipe-import/stacy-token.txt` holds a user token. Rotate both, gitignore `.recipe-import/`.
2. **Fix the `Database` type → clears 116 of 135 tsc errors (86%).** The hand-written type in `src/types/database.ts` fails supabase-js v2's `GenericSchema` constraint (missing `Views`/`Functions`/`CompositeTypes`/`Relationships`), collapsing every table to `never` — which forced the `as never` casts and hides real type bugs (the PlanGrid `display_name` bug was in this class). Fix: `npx supabase gen types typescript --linked`, alias app interfaces to `Tables<'x'>`, remove casts, then add `tsc -b` to the definition of done. Remaining 19 errors are mechanical (list in tsc audit).
3. **Broken links:** `StandaloneCookPickerPage.tsx:103` navigates to `/recipes/new` (renders RecipeBuilder against literal id "new"); `MealBuilder.tsx:274` navigates to `/meals` which doesn't exist (404).
4. **import-recipe breakfast rule** still uses the weak pre-L-039 wording while recipe-supply has the strict version — L-039 requires they match.

### P1 — close the weekly loop (highest product leverage)

The audit's biggest UX theme: every stage of Stock → Compose → Shop → Cook → Rate renders
well in isolation, but only Grocery→Plan has a cross-stage link. Four missing edges:

5. **Stock → Compose:** DiscoverRecipesModal just closes after adding — add a "Go plan the week" CTA in its success state.
6. **Compose → Shop:** after generation completes, nothing points at Grocery — add a "Generate grocery list" CTA next to the generation badge.
7. **Cook → Rate:** Cook Mode completion shows the deduction receipt then `navigate(-1)` — no rating prompt, despite rating being the flywheel. Add rate-this-meal to the receipt.
8. **Shop → Stock:** checked-off grocery items never enter inventory — add "shopping done → add purchased to pantry".
9. **Today page has no Cook affordance** — the "Tonight" panel is display-only (the Guide previously claimed otherwise; Guide was corrected, but the button is the better fix and also gives `/cook` a reachable entry point).

### P2 — data cleanup (prod)

10. 19 recipes are untagged wildcards again (regrown post-backfill), 2 still over-tagged (3+ slots), 3 recipes have zero ingredients, and 8 of 147 meals have no meal_items (the L-033 zero-kcal class). One admin pass: classify per household, trim over-tags, delete the empty artifacts.

### P3 — coherence & polish

11. **Design-system stragglers:** InsightsPage and SettingsPage (both in main nav) are fully old-style; RecipeBuilder is old-style inside the editorial Recipes flow; ~800 old-style class occurrences across 101 component files. Migrate page-by-page: Insights, Settings, RecipeBuilder, Cook Mode.
12. **Delete the dead Meals concept:** `/meals/:id` route + MealPage + MealCard are orphaned (nothing renders MealCard); contradicts the "recipes get planned" model.
13. **Naming:** HomePage(=/today) kicker says "HOME" while nav says "Today" and "Home" is a different page; Insights headline "Taste Insights" breaks the editorial "The ___" convention; Folio says "PAGE X OF 10" but only 6 pages have folios. Consider renaming files (HomePage→TodayPage, WelcomePage→HomePage).
14. **Welcome overpromises:** blurb says "nutrition and spending trend over time"; Insights only shows recipe ratings + AI tags. Either soften or build trends (a real weekly trends view — kcal vs target, spend vs purse — would also serve the guide's monthly review ritual).
15. `role="tabbar"` on TabBar is not a valid ARIA role — drop it.
16. **Repo hygiene:** 492 untracked files (418 `.playwright-mcp/` snapshots, ~30 root demo PNGs, `.recipe-import/`). Gitignore `.playwright-mcp/`, move demo PNGs out or delete, and commit the 3 modified `.planning/` phase docs that record UAT closures.

### Standing gaps (carried from milestone close, still true)

- No production error monitoring — edge-function failures are invisible until a user reports (L-034 class). Cheapest fix: a Sentry (or even a log-drain) on the SPA + function error webhooks.
- Edge functions have zero automated tests; the suite's tripwire tests grep source strings. A thin Deno test harness for sanitizers/guardrails would cover the riskiest logic.
- 22 deferred human UATs from v2.0 (DnD gestures, schedule grid picker, recipe-mix sliders end-to-end); IMPORT-03 YouTube transcript success rate unmeasured.
- No CI: tests and typecheck run only when someone remembers. A GitHub Action on push (vitest + vite build, later tsc -b) turns this audit's green state into a ratchet.

## Suggested order of attack

1. P0 items 1–4 (an afternoon, mostly mechanical; the types fix is the big unlock).

3. CI + error monitoring (turns everything above into a maintained state, not a snapshot).
4. P2 data pass + P3 editorial migration as background work per page touched.
